# Technical report style guide

**Not for:** RFC (`rfc-generator`), ADR (`adr-generator`), academic paper (`academic-report-generator`). After draft: **tech-report-reviewer**.

**Tone:** Direct, neutral; separate observation / interpretation / recommendation; no fabricated metrics - placeholders + call out gaps.

**Structure:** `#` once; `##`/`###` for sections; exec summary for long docs; bullets for findings/risks/actions; tables for comparisons/metrics.

**Audience:** Team = detail + team acronyms OK. Leadership = less jargon, impact + decisions. Handoff = owners, open questions, where artifacts live.

**Formatting:** Code/config only when supplied or labeled pseudocode. Links as `[describe link]` not fake URLs.
