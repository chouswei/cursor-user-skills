# Unsync checkpoint pipeline

Named mechanism: Plan and Execute stay the roles. Runtime is an unsync multi-task pipeline. Execute is atomised parallel workers (one atom = one path, qname, or proof). A checkpoint is a coordinator turn after a wave, not a worker self-declaration. Model nicknames are not role pins; map them only in Model by role.

## Model by role

- Plan = Opus, `claude-opus-5-thinking-medium`; rare top-level planning or deep diagnosis only.
- Detail = Grok, `cursor-grok-4.5-medium`; bind concrete scope, interfaces, and execute atoms.
- Execute = Luna, `gpt-5.6-luna-high`; implement and verify one atom once Bind ready.
- Web = Gemini3, `gemini-3-flash`; fetch live web or library documentation.
- Visual = Kimi, `kimi-k3-high`; review visual items.
- Prose = Gemini3.8, `gemini-3.8-flash`; prose author.
- Unclear = Grok, `cursor-grok-4.6-high`; resolve an uncertain route.

## Runtime

1. Parent is coordinator: mint and settle `TSK_*` / `USR_*`; MUST NOT do a worker's role when that role applies.
2. Non-trivial work: split into waves (same wave = disjoint scopes only; else serial). After Bind ready, spawn one Execute worker per execute atom in that wave. MUST NOT hand one Execute worker a bundled sequential job. Spawn one worker per ready step with that step's role model.
3. MUST spawn unsync (background / Multitask). MUST end the turn after spawn -- no poll, no await.
4. Next coordinator turn is a checkpoint: `pin_map` first; settle from graph facts and proof commands; spawn the next ready wave or stop.
5. One role model per step (no committee on the same atom). Many Execute workers in one wave is not a committee.
6. Trivial single-tool answers stay in the parent. MUST NOT spawn Task for those.

## Checkpoints

- Plan accept -- Plan output accepted, or skip when the plan exists, the design is user-bound, or the patch is obvious.
- Bind ready -- Detail bound purpose, paths, interfaces, and execute atoms; Execute atoms may start in parallel.
- Execute proof -- each execute atom's proof commands produced sane output.
- Review pass -- Visual, Web, Prose, or Unclear only when that role is needed.

Human gate: Plan accept when architecture is user-bound. Other checkpoints are coordinator-auto unless the user asked to review.

## Gates

- MUST NOT spawn Plan except for a rare top-level plan or deep diagnosis.
- MUST skip Plan when the plan exists, the design is user-bound, or the patch is obvious.
- MUST NOT hand Execute work until Bind ready. Bind MUST emit atomised execute steps.
- MUST NOT use Plan or Detail as the Execute worker when Execute applies.
- MUST NOT use Execute for planning, visual review, or web search.
- MUST use only live, non-`*-fast` model slugs.

SysML gate:

- MUST NOT send `.sysml` edits, the SysML skill stack, or bulk SysML text to Plan.
- Detail or the parent MUST bind purpose, packages, part/port/qname, and paths only under the repo SysML SSOT, usually `sysml-models/`. MUST NOT assume `sysml-models/models/` unless that path exists.
- Execute MUST apply `.sysml` edits only after Bind ready, then sync outputs and update allocated `parts/**` programs.
- Plan MAY make only a short architecture decision with problem and path/qname pointers; do not attach or paste model files.

When Multitask Mode is on, the system gate wins: MUST spawn async, MUST end the turn. Follow `~/.cursor/skills/memnet-multitask/SKILL.md`.

# MemNet

Use the GQL wire from `~/.cursor/skills/memnet-format/SKILL.md`; chat is not durable mission state.

When: multi-turn, 3+ step pipelines, SysML, or user constraints. Skip: one-shot, trivial edit, MemNet tools absent, or serve down. When skipped, use plain Markdown only.

Under Multitask Mode or Task sub-agents, follow `~/.cursor/skills/memnet-multitask/SKILL.md`. MUST use one shared MemNet session over TCP `:18765` or streamable HTTP `:18766/mcp` bridged to that serve; MUST NOT use in-process MCP. Parent and worker share the session; worker calls `pin_map` first, mutates only its assigned subgraph, and MUST NOT settle parent-owned `TSK_*` or `USR_*`.
