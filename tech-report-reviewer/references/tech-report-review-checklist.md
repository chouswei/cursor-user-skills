# Technical report review checklist

**Scope:** Markdown/plain technical reports. **Not:** `code-reviewer`, `pr-reviewer`, RFC ballot process, or academic peer review unless user asks.

**Structure / navigation**

- [ ] Title, date, audience, purpose visible early.
- [ ] Logical headings; no orphans or duplicate titles.
- [ ] Exec summary (if any) matches body; no orphan claims there only.
- [ ] Scope / out-of-scope when topic is broad.

**Clarity / tone**

- [ ] Jargon fits audience; scannable lists; hedging matches evidence strength.

**Evidence**

- [ ] Metrics/dates/tests: supplied, cited, or **placeholder** - not fabricated.
- [ ] Conclusions supported; limitations visible.

**Technical / actionability**

- [ ] Assumptions and dependencies where they drive conclusions; tradeoffs when recommending.
- [ ] Risks vs stakes; next steps with owners when doc drives work; no fake URLs.

**Pairing:** Empty/unusable draft -> suggest **tech-report-generator**.
