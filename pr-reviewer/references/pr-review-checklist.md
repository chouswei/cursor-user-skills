# PR Review Checklist

## Breaking Changes & Migration
- Are there breaking changes?
- Is a migration guide or deprecation plan provided?
- Are version bumps appropriate?

## Code Quality
- Does the code follow team style and conventions?
- Are functions reasonably sized and focused?
- Is error handling comprehensive?

## Documentation
- Are new features or changes documented?
- Are public APIs documented?
- Are there any missing comments on complex logic?

## Testing
- Are tests added or updated for the changes?
- Do tests cover edge cases?
- Are tests readable and maintainable?

## Security & Performance
- Any new security risks introduced?
- Any obvious performance regressions?
- Are secrets or sensitive data handled correctly?

## Overall
- Does the PR description clearly explain the change?
- Are related issues or tickets linked?
